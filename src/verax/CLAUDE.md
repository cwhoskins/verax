# Package-root modules

`src/verax.nim` is the top-level package module; it is intentionally *not* a re-export hub — submodules (`submodule.nim`, `netlist.nim`, `schematic.nim`, `spice.nim`, `analysis.nim`, `pcb.nim`, `contract.nim`, `parts.nim`, `ibis.nim`, `fem.nim`) are imported directly by their own path (e.g. `import verax/netlist`), not through `verax.nim`.

Each submodule directory carries its own `CLAUDE.md`: `netlist/`, `schematic/`, `spice/` (and `spice/xspice/`), `analysis/`, `contract/`, `pcb/`, `parts/`, `ibis/`, `fem/`.

Three package-root modules sit outside any submodule because the dependency order (`netlist` <- `spice` <- `analysis`, `netlist` <- `pcb`, `netlist` <- `contract`) gives them nowhere else to live — but for two different reasons. `units.nim` and `eng.nim` sit *below* every submodule: more than one needs them and none may own them. `verify.nim` sits *above* every submodule: it needs `contract` and `analysis` at once and neither may depend on it.

`src/verax/units.nim` is typed electrical quantities — `Volts`/`Ohms`/`Farads`/`Henries`/`Hertz`/`Seconds`/`Amps`/`Fraction`, plus `Degrees`, `Decibels` and `Celsius` which are not electrical and are here because the role registry declares `minPhaseMargin` in degrees and `maxPeaking` in dB, and a bare `50.0` in a list of unit literals is precisely the misread this module removes. A `Decibels` stores the dB figure rather than the ratio it denotes, because every consumer compares against a measurement already in dB. Note Nim reads `dB` and `db` as one identifier, so both spellings work. `Celsius` is the one type carrying two *different* quantities — an absolute temperature (`t_ambient_max = 70.degC`) and a temperature difference (`delta_t = 16.degC`) — which the key each is stated under distinguishes and which nothing here enforces, since this is deliberately not a dimensional-analysis system; `netlist/environment` is the only code that adds them. It is also the one type rendered **without** SI prefixes, because a half-degree rise printed `500 mdegC` is exactly the misread the module exists to remove, and there is no kelvin constructor for the same reason: `20.K` as a rise is 20 degC and as an absolute temperature is -253 degC, and one suffix cannot mean both. With suffix constructors (`3.3.V`, `20.mohm`, `600.pH`, `400.kHz`, `5.pct`) that scale to SI base units. It exists for one reason: `esr = 20.mohm` cannot be misread, whereas `"20m"` and `"0.02"` differ by a thousand and look equally plausible. **Deliberately not a dimensional-analysis system** — no unit arithmetic, no derived units, no compile-time dimension checking; adding those is a much larger design that buys nothing for the job at hand. Distinct from `pcb/units.nim`, which is board *geometry* (`Nm`/`Deg`); the type names and suffixes are disjoint.

`src/verax/eng.nim` is the one package-root helper: `eng(x, unit)` renders a float in engineering notation with an SI prefix (`20.1 mohm`, `600 pH`, `15.9 MHz`) for report text and messages. It sits at the root because both `spice` and `analysis` need it and `analysis` already depends on `spice`. It is **presentation only** — a value written into a deck must go through `netlist/formats/spice.spiceValue`, which always emits an explicit exponent, because SPICE reads a trailing letter as a unit multiplier (`15.9M` in a deck is 15.9 *milli*).

`src/verax/verify.nim` is the runner: it checks a `Design` and renders one *readiness report*. It is the only module that imports `contract` and `analysis` together, which is why it cannot live in either — `contract` must never gain an edge to `analysis`, since a design staying inspectable with no simulator in the build is what that separation buys. When `$VERAX_KEEP_RUNS` is set it calls `schematic/render.keepFullSchematic` before `readiness` runs — which writes `runFULL.svg` and its `runFULL.json` scene (a schematic of the authored `Design.netlist`), one `runFULL.<subckt>` SVG/JSON pair per distinct subcircuit (deduplicated by `Netlist.name`, so a block instantiated twice is drawn once, each with its `nl.ports` as Altium-style port symbols), and one **`runFULL.html`** hierarchy browser. All best-effort and overwritten each check, so the run archive carries the design as written beside the derived `runNNN.svg`/`runNNN.json` fragments, and never as `index.txt` rows. That whole subsystem — `writeScenePair`, `ExplorerSheet`/`explorerSheet`/`renderExplorerHtml`, `keepFullSchematic`, `safeSheetName` — lives in `schematic/render.nim` (see `schematic/CLAUDE.md`), not here: it needs only `netlist`, so `verify` calling it costs nothing extra and `spice/ngspice` reuses `writeScenePair` for its `runNNN` pair. Archive pictures alone honour
`$VERAX_SCHEMATIC_LAYOUT` (`historical` by default; `constrained-layered`
when selected by `--schematic-layout`); it never changes simulation or an
ordinary `layout` call. None of these is an `index.txt` row — the index names analysis runs, and a picture is not one.

**It imports `analysis/evaluators/contract_eval` unconditionally, and that is the point.** Without it a perfectly good requirement reports `no evaluator produces 'z_max_in_band'` — which is false; `spice.pdn` produces it, the module registering that evaluator merely was not imported. A reader who believes the message deletes a correct requirement. With one entry point that always registers the simulated evaluators and gates on *capabilities* instead, the same claim reports `requires capSpiceAc, which was not offered` — true, and it says what to do about it. What is *offered* remains the caller's choice (`allowed`), so nothing is forced to simulate.

The report reads back the design's stated `environment:` — the ambient range and the hottest part in it — and only when it was stated: nothing is temperature-dependent yet, so nagging every design would be noise, but a premise quietly carried is a premise nobody checks. The report is **rendered fresh, not composed** from `report`/`summary`/`explainPlan`/`explain`. Each of those answers one question in isolation and each re-lists the same assertions, so concatenating them prints one failing claim three times; the ordering and de-duplication *are* the product. Sections run in order of how much each undermines everything below it — structure, **checks**, failures, **not checked** — and `NOT CHECKED` is the centre of gravity, never collapsed: an assertion nobody evaluated is not one that passed, and silence reading as approval is the failure mode the contract layer exists to prevent. A failed or unchecked result also prints any `Issue` attached to it, **de-duplicated across the whole report** — evaluation is batched, so one loop-gain run's diagnosis rides on every claim in its batch and would otherwise print once per claim. A *passing* result's issues are not printed: it passed.

**The body is `CHECKS`: one block per *test*, where a test is one analysis run.** That grouping is the plan step seen after running, and it is the only one that recovers three facts a flat list of results loses — which claims came out of one simulation (so a single wrong setup explains all of them at once), what that simulation *was*, and which invented values it rested on. It cannot be recovered after the fact: an `AssertionResult` carries its evaluator's name but not its setup key, and two steps of one evaluator are two different runs. So `readiness` goes through `runPlan` (which returns one `seq` per step) rather than `evaluate` (which flattens), and `Readiness` gained `checks: seq[Check]` and `rejected`, with `results` kept as the flat concatenation so `summary`/`failed`/`invented` go on working. Each block carries three things. **`ran:`** — what was actually simulated, from a new `Evaluator.setupDoc` proc field beside `setupKey`; the key exists to *group*, and `vdd|100000.0|100000000.0` is a correct key that says nothing about what was simulated, while the fragment handed to ngspice is derived rather than authored and so needs saying. A `nil` `setupDoc` falls back to the key, and one that raises is caught, on the same reasoning as `previewRole`. **`assuming:`** — the batch's own assumptions, deduplicated, `annAuthored` excluded. Pooled at the foot of the report they said forty values were invented *somewhere* and left the reader to work out which number each one moved; under the run that rests on them the question is answered. `foldAssumptions` collapses records sharing `(key, value, unit, detail)` onto one line naming every entity — lossless, and it took one design's PDN block from 39 lines to 21, which is the difference between a list read and a list skipped. That is also why `annotations.note` gained a `note(entity, detail)` overload: a designator baked into the sentence cannot be folded on, and `$Assumption` renders the two forms identically. **The claims** — one identity line (id, quantity, subjects, and `conditionText`, which spells `[f_from=100k, f_to=100M]` as `over 100 kHz .. 100 MHz`), one comparison line putting `expect` and `measured` together with `acceptance` rendering a tolerance as the interval it accepts, and `because …` — `Assertion.rationale`, which was previously printed nowhere at all — whenever the claim did not pass. `FAILED` and `NOT CHECKED` render through the same `renderClaim`, so a limit is not spelled two ways in one report, and claims that reached no test are counted in `CHECKS` but listed only under `NOT CHECKED`, since printing them twice teaches the reader to skip one of the two places. `capLabel` moved to `contract/evaluate` so a withheld capability reports `needs the .op capability` rather than the enum identifier `capSpiceOp`. A `Readiness` holds `AssertionResult`s and `Issue`s and **never an `AnalysisReport`** — `AssertionResult` has no field for one, so `raw`'s thousands of curve points cannot leak in; a test pins the rendered size so a future "attach the curve for context" change fails loudly.

Two things it reports that nothing else can. `didYouMean` ranks `evaluableQuantities()` by edit distance when nothing produces a quantity, because a misspelling is the likeliest way to write an uncheckable claim and `no evaluator produces 'z_ripple'` alone says the door is locked without mentioning a door exists. And `claimLint` catches a claim that states no unit against a quantity measured with one: `unitsAgree` treats an empty unit as "not stated, therefore unchecked", which is right for a bare count like `pullup_count` and dangerous elsewhere — `unitOf(Fraction)` is `""`, so `require overshoot_pct(vdd) <= 5.pct` compares 0.05 against a measurement of 5.0 and is wrong by a hundred with nothing said. The real fix is a `units` field on `Evaluator` parallel to `produces`; until then this reports it after the fact rather than comparing silently.

`describeQuantities` reports *reachability* alongside each quantity, computed by `claimingRoles()` — which expands every registered role with every parameter stated, and then each parameter on its own, because a parameter can **redirect** a claim rather than add one (`gain_stage`'s `atF` moves the gain claim from `gain_max_db` onto `gain_at_f`, so either expansion alone hides a branch the other shows). Computed rather than written down for the same reason `previewRoleDelta` is: a hand-kept list is exactly the thing that drifts from the expanders, and this is the answer a reader is about to act on. Listing quantities without it invited the obvious mistake — ten of twenty-six were unreachable by any built-in path and nothing said which. `verify.nim` also holds the **catalog** — `describeRoles`/`describeRole`/`describeQuantities`/`describeAnnotations`, rendered to strings rather than printed because the CLI echoes them and the MCP server returns them. `previewRole` expands a role against placeholder bindings (safe: `RoleExpander` takes only a `RoleInstance` and never touches a netlist — that is exactly what separates `expand` from `apply`), and `previewRoleDelta` finds which *parameter* buys which extra claim by diffing two expansions, so that documentation cannot drift from the expander. An expander that raises yields nothing rather than propagating: a third-party role must not make `verax roles` unusable.

`src/verax/cli.nim` is the `verax` binary — thin over the above, with one piece of real logic: it locates verax's sources for `--path:` through a chain of *validated* candidates (`--path:` flag, `$VERAX_PATH`, a repo checkout found by walking up for `verax.nimble`, the compile-time `currentSourcePath()`, `nimble path verax`), falling back to passing no `--path` at all, which is correct for a design repo that has run `nimble setup`. Each candidate is checked for `verax/contract/dsl.nim` rather than trusted — nimble builds a package that declares binaries inside a temporary directory and deletes it afterwards, so the compiled-in path can dangle for an installed copy. It compiles and runs a design as **two processes, never `nim c -r`**, because that merges "this file does not compile" with "an assertion failed" into one exit status.

The trap that made this necessary, recorded because the fix is easy to undo: `voltage_source` is in `kinds.conductiveKinds`, so `isPassive` is true and a PDN isolation *absorbs* a supply rather than cutting it — and an ideal source is a dead short at AC. Verified empirically, the same rail measured 129 mohm with no source and **0 ohm with one**, passing every target that could be set. `spice/models.expandSourceImpedance` is what stops that, and removing it silently restores a check that always passes.
