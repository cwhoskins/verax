# `pcb` submodule

`src/verax/pcb/` models the *physical* board — layers, stack-up, copper, holes, component placements, board outline — and is where any future DRC/DFM/SI/PI work lands. It depends on `verax/netlist`; the netlist never depends back on it. `src/verax/pcb.nim` is the hub (`units`, `geometry`, `types`, `graph`, `index`, `bom`, `trace`, `impedance`, `tline`); file formats stay opt-in per-import under `pcb/formats/`, same as `netlist/formats/` and `spice/ngspice`.

**The electrical model is not duplicated.** A `Pcb` *owns* a `Netlist` built through the ordinary `netlist/graph` API, and every PCB entity holds a **forward reference only** into it (`Copper.net: Net`, `Copper.pin: Pin`, `Placement.component: Component`). `netlist/types.nim` is untouched and stays geometry-free, so a netlist-only consumer carries none of this weight while an analysis pass can still walk from a trace to the pins it connects in one hop. `Placement`/`Component` normally join on reference designator (`bindComponent` enforces the match; `placementOf` is the reverse lookup). **The one exception is a multi-channel package**: a dual op-amp is one `Placement` and two netlist `Component`s (its sections), joined through the component's `package.ref` (`netlist/packages`). `bindComponent` then records the component in `Placement.sections[sectionName]` and leaves `Placement.component` **nil** — there is no single netlist component a dual op-amp *is*. `addLand` for such a placement treats the pin name as a *package pad id*, resolves it through the definition's pin map to `(section, logical)` and binds from that section's own pin (pad `"7"` on an NE5532 → section B's `OUT`; an undeclared pad id binds nothing rather than guessing). `bom.nim`'s `partNumberOf`/`footprintOf`/`packageDefOf` fall back to the shared `PackageDef` when `component` is nil, so N sections collapse to one `BomLine` for free (`buildBom` was always one-placement-one-line). `placementOf` falls back to a scan of `Placement.sections` since the placement is keyed by the package designator, not the section's.

- **Two lookups are first-class**, because they are what layout analysis actually asks. By **net name**: `Pcb.netCopper` (name -> every `Copper` on it), maintained by `pcb/graph`, queried via `copperOn(pcb, netName | net, layerName = "")`. By **location**: `pcb/index.nim`, a per-layer uniform grid over cached per-feature AABBs. `query`/`queryPoint`/`near` are bounding-box *candidates*; `hitTest` applies the exact `geometry.contains` predicates on top — do not confuse the two. Any feature spanning more than `SpatialIndex.maxCells` cells (a board-sized pour) goes to a per-layer `oversized` list instead of into every bucket; that overflow is the one thing that makes a uniform grid viable on PCB data. `graph` sets `index.dirty` on every mutation and every query rebuilds when it is set, so callers never manage the index by hand.
- **`units.nim`** — `Nm = distinct int64` nanometres and `Deg = distinct float64` degrees, with `mm`/`mil`/`inch`/`um` constructors and `toNm(v, LengthUnit)` for readers. `int64` nm spans the whole ODB++ coordinate range (±2450 mm) and exactly round-trips KiCad (int32 nm internally). Known, deliberate loss: ODB++'s finest legal quantum is 1/400 µm = 2.5 nm, so ODB++ input rounds to the nearest nm — far below any fab tolerance. **Canonical frame: X right, Y *up*, angles CCW-positive, degrees; polygon winding islands CCW / holes CW.** ODB++ and Gerber are already Y-up; KiCad is the outlier (Y-down, rotation CCW-as-displayed) and its reader must negate Y and angle at the boundary, or every rotated footprint silently mirrors.
- **`geometry.nim`** — the dimensionless `Curve` (`cvSeg`/`cvArc`) is deliberately separate from the `Shape` that has area (`shStroke` for tracks, `shFill` for pours, `shPad` for a flashed aperture, `shText`). **Arcs are canonically centre + radius + start angle + signed sweep**, since KiCad's three-point form and ODB++'s endpoints-plus-centre form are both awkward for AABBs and sampling; `arcFrom3Points`/`arcFromEndpointsCenter` convert once, at the reader. `Aperture` is a `ref object` **interned in `Pcb.apertures`** (mirroring ODB++'s `$n` symbol table and KiCad's shape tokens) so one object backs thousands of pads; its raw source `name` is kept verbatim even when parsed, and unrecognised names fall back to `akCustom` rather than erroring. `Transform` does footprint-local -> board coordinates.
- **`types.nim`** — `Pcb`, `PcbLayer`, `Stackup`/`StackEntry`/`StackMaterial`, `Copper`, `Zone`, `Hole`, `Placement`, `Outline`, plus `SpatialIndex`'s *storage* (its algorithms live in `index.nim`; the type is declared here only so `Pcb` can hold one without a circular import). Every entity carries the same open-ended `attrs: OrderedTable[string, string]` bag as `netlist/types`, so a format module never extends this schema.
- **`graph.nim`** — as with `netlist/graph.nim`, **the only place allowed to mutate back-references and indexes**. Nothing else sets `.pcb`, `.layer`, `.net`, `.pin`, `.hole`, `.pads`, `.lands`, `.box`, `.sourceIndex` or `.index`. Use `addLayer`, `addCopper`, `setNet`, `setShape`, `removeCopper`, `addZone`, `addHole`/`attachPad`/`setSpan`, `addPlacement`/`bindComponent`/`addLand`, `internAperture`, `addStackEntry`.
- **Layers are keyed by name, never by ordinal** — KiCad renumbered every layer ID in v9 (`B.Cu` went 31 -> 2, inner layers to `2+2n`) and ODB++ `ROW` numbers are explicitly allowed to be non-sequential. `Pcb.layers` **insertion order is physical stack order**, so readers add top to bottom.
- **Ordinal warning**: ODB++ cross-references everything positionally (`FID` feature numbers, `CMP`/`PKG`/`NET` record indexes). `PcbLayer.copper` is kept in source order and must never be re-sorted or deduped; `Copper.sourceIndex` is only meaningful immediately after a load, and `removeCopper` renumbers it (and says so).
- **`Copper.negative`/`PcbLayer.negative`** exist because ODB++ `POWER_GROUND` layers are routinely `POLARITY=NEGATIVE`, where drawn features are *clearances*, not copper. A by-net copper index that ignores this is exactly inverted on every plane layer.
- **`Hole`** unifies two very different encodings: KiCad states the layer span directly, while ODB++ has no hole record at all (holes are pad features on a `TYPE=DRILL` layer, classified by the matrix row's `START_NAME`/`END_NAME`, the `.drill` attribute, and the layer's `tools` file keyed by the feature's dcode). `setSpan` derives `vkThrough`/`vkBlind`/`vkBuried` from which outer layers the span touches. `drillDia` and `finishedDia` are separate because ODB++ `tools` distinguishes them.
- **`Zone` models both the *authored* outline (`outline`/`areas`) and the *derived* fill (`fills`, added this stage).** They are different claims about a board — what the design says to pour versus what a fill pass actually produced after clearances, thermal reliefs and priority against other zones — and only `fills` is real copper: `graph.addZoneFill` lands one `ckFill`/`shFill` `Copper` per filled polygon into `Pcb.netCopper` and the spatial index, same as any other feature. `fills` is empty on an unfilled board and on a keepout (nothing is ever poured there); a caller must treat empty as "not answerable", never as "no copper" — `fem/extrude.extrudeZones` is the worked example, refusing **per zone** rather than meshing `outline` as a solid slab that would omit every relief and clearance. The one hazard this creates: `graph.addZone` already pushes a `ckZone` record of the *authored* outline onto each of the zone's layers, so `extrudeCopper` must skip `ckZone` explicitly (`cu.kind == ckZone: continue`) or a plane gets meshed twice — once wrong (the outline, as solid copper), once right (`fills`).
- **`bom.nim`** — `buildBom(pcb, groupBy = nil)` *compiles* a BoM from what the board file already carries; it does **not** resolve parts against a supplier catalogue (that is a separate `verax/bom` concern). Both formats do carry per-part data on the board itself — KiCad `(property "Reference"/"Value"/...)` plus schematic-propagated user fields and `dnp`/`exclude_from_bom`; ODB++ `PRP` records plus an explicit `BOM DATA` block (`CPN`/`IPN`/`DSC`/`VND`/`MPN`/`VPL_*`) — so a reader drops all of it into `Placement.attrs` and `bom.nim` promotes the well-known keys, trying both naming conventions. `excludeFromBom` placements are dropped; `doNotPopulate` ones are **kept** on their own lines.
- **`formats/common.nim`** — the format contract is **path-based, not `Stream`-based**, a deliberate departure from `netlist/formats/common.nim`: an ODB++ job is a *directory tree* whose members may be LZW-`.Z` compressed, which no single `Stream` expresses; a KiCad board is one file, so a path covers both. `proc readPcb*(path: string, step = ""): Pcb` / `proc writePcb*(pcb: Pcb, path: string)`; the `step` param exists because one ODB++ job may hold several steps (board/panel/coupon). **`formats/kicad.nim` implements this contract now**; `formats/odbpp.nim` is still unwritten.
- Two gotchas that shaped `formats/kicad.nim` and remain live for `formats/odbpp.nim`: KiCad has **no explicit board outline** (it must be stitched from `Edge.Cuts` graphics with a tolerance — hence `Outline.stitchTolerance` — *including items owned by footprints*), and **ODB++ net names are not unique** (the spec calls them "for reference only"; the reserved `$NONE$` repeats with mutually-disconnected meaning), so a reader must synthesise unique names before registering into the name-keyed `Netlist.nets`/`Pcb.netCopper`.

## `formats/kicad.nim`: the KiCad `.kicad_pcb` reader/writer

Full module documentation lives in `formats/sexp.nim` and `formats/kicad.nim`'s own doc comments — this section is the index of *decisions*, each naming the silent failure it prevents, the house standard.

- **Verbatim emission is not an optimisation; it is the only way to meet "byte-exact".** Measured on `interf_u.kicad_pcb`: its `(xy ...)`-per-line counts are 1x5, 2x12, 3x4, **4x2341, 5x135** — no single column-count rule explains both ends of that distribution, because KiCad's writer runs everything through a `Prettify()` pass this library cannot reproduce by rule. `formats/sexp.nim` is the answer: every node is an `(offset, length)` slice into the source `string`, and an untouched node is written by copying its bytes. A node nothing has edited needs no escape rule, no quoting policy and no number formatter to get right, because its raw bytes already are correct — this is what makes a reader with real coverage gaps (see below) still round-trip byte-for-byte.
- **The corrupt demo board, and why `kicad-cli` exiting 0 proves nothing.** `/usr/share/kicad/demos/royalblue54L_feather/RoyalBlue54L-Feather.kicad_pcb` is corrupt as shipped: 349 occurrences of `)filter_ratio 0.9)` where `(filter_ratio 0.9)` was meant, each missing its opening paren. Total `(` count is 125872 against 126221 `)` — exactly 349 more closes than opens. The nesting drifts far enough that the `(kicad_pcb` root closes near line 627 of a 69,495-line file and everything after becomes independent top-level fragments. `kicad-cli pcb drc` on it **exits 0**, reporting "Found 283 violations, Found 0 unconnected items" — it read about 1% of the file without complaint. This forces a real split: `sexp.parseSexp` **never raises** on a structural defect (a stray `)` with no matching `(` is absorbed as ordinary gap content, never raised on — see that module's doc comment), so the s-expression layer round-trips this file too, structurally; `kicad.readPcb` is the layer that turns "not exactly one well-formed `(kicad_pcb ...)` root" into a named refusal. Refusing by name, with a line number, is strictly better than KiCad's own tooling here.
- **`Pcb.source: RootRef` + `attrs["kicad.node"]`, not a `KicadBoard` wrapper.** The contract is `writePcb(pcb: Pcb, path: string)`; a wrapper the caller must hold onto changes that signature and breaks the one thing `formats/common.nim` exists to guarantee. `RootRef` is the same type-erasure move `contract/evaluate.EvalContext.scratch` already makes for the identical layering reason (`pcb/` must not gain an edge to a format module). `attrs["kicad.node"]` (a stringified node index) rather than an identity-keyed side table, because `kicad.*` is already reserved and never validated (`netlist/annotations.nim`), `attrs` already survives every clone path, and it is greppable in a debugger. `(uuid)` deliberately does **not** go in `attrs` — it is the single most common token in the corpus (376,804 occurrences in the jetson board alone) — reached instead through the mapped node on demand.
- **`Pcb.rev` and the byte-exactness limit it encodes.** One monotonic counter, bumped by `graph.touch` and stamped into the touched entity's own `rev` at the same time, so "changed since T" is `entity.rev > T` with no separate dirty flag and no way for two entities to disagree about which changed more recently. `KicadDoc.snapshotRev` is `pcb.rev` at the moment `readPcb` returns; `writePcb` takes the fast path (`render(fastPath = true)`, i.e. return the source bytes untouched) exactly when `pcb.rev == snapshotRev`. That fast path is *why* a reader with real coverage gaps still guarantees byte-exactness for the untouched case — the writer never looks at what was or was not mapped unless something actually changed.
- **The regenerator set is deliberately narrow, and the refusal table is the other half of the contract.** Ships this stage: `(segment)`/`(arc)`/`(via)` (whole-node, for both modify and insert), `(net N "name")` (insert-only, new nets never renumber an existing code), field-level overrides on a footprint (`(at)`, `(layer)`, the `Reference` property's value, a pad's `(net)`) and a zone's scalar fields (`net`, `net_name`, `priority`, `name`). Refused **by name**, naming the entity and the class: a new footprint or pad on a board that already has a KiCad source (nothing in the *edit* path carries a padstack or the graphics a synthesized footprint would need), any `PcbLayer.shapes` edit (silkscreen/mask/courtyard/fabrication — `Shape` has no per-shape identity to track at 326,626 `fp_line` nodes on the largest demo board, so a change is detected only at `PcbLayer.rev` and turns into a refusal, never a silent stale write), a new zone (its outline/fill would have to be fabricated), and any stack-up edit (`(setup (stackup))`'s child order *is* the physical stack). The one-sentence capability boundary for docs, revised now that a from-scratch board exists: **on an already-sourced board, route, re-route, rip up, re-net, re-pour and move — do not create or reshape a component; on a `Pcb` with no source at all (`pcb.source == nil`), `writePcb` takes the synthesis branch instead (see `assemble.nim`/`formats/kicadgen.nim` below) and *can* create a component, because it is never inventing KiCad's own graphics syntax — it is quoting a real `.kicad_mod`'s bytes.**

- **`footprint.nim`, `formats/kicadmod.nim`, `formats/kicadgen.nim`, `assemble.nim`, `variant.nim`: the schematic → PCB stage.** Four gaps stood between a checked design and a board file — no way to state a footprint, no footprint geometry model, no netlist-to-blank-`Pcb` path, and `writePcb`'s hard refusal on a new footprint — and this is what closes them, plus the data model (only) for multiple layouts of one subcircuit.
  - **`netlist/annotations.nim` gained `footprint`** (component-scope `akString`), read here via `footprint(c: Component): AnnValue[string]`. Deliberately separate from the existing `package` key: `package` is a *case size* keying `spice/models`' parasitics table (`"0402"`, `"tantalum"`), and two parts sharing a case size can need different land patterns (hand-solder vs. reflow). `spec: footprint = "Lib:Name"` needs no DSL change — `spec:` already validates any registered key at compile time.
  - **`footprint.nim`** is the type the repo lacked: `Footprint`/`FootprintPad` (a pad's `id` is the same join key `graph.addLand`/`PackageDef.pins` already use for a pin), plus a `FootprintSource` provider registry — pure data, first-registered-source-that-resolves wins, **no built-in source registered here**. `Footprint.source` holds the defining `(footprint ...)` node's verbatim bytes, on the identical bet `formats/sexp.nim` already makes for a board: an untouched node needs no escape rule or number formatter because its raw bytes already are correct. That is also what makes the revised capability boundary above liftable at all — a synthesized board can carry a real footprint because it is *quoting* one, never inventing KiCad's graphics syntax by rule. `FootprintPad.layers` is raw, unexpanded KiCad tokens (`*.Cu`, `F.Mask`): a bare `.kicad_mod` file has no target board to expand a wildcard against, so expansion is deferred to whichever module places the footprint onto a real `Pcb`.
  - **`formats/kicadgeom.nim`** holds the KiCad geometry helpers (`buildAperture`, `expandPadLayers`, `readXy`/`readMm`/`readDeg`, `graphicCurves`/`graphicNodeLayer`) shared between `formats/kicad.nim`'s board reader and `formats/kicadmod.nim`'s library reader — extracted rather than duplicated, because a divergence between the two (a roundrect ratio parsed one way in a board and another in a library) is invisible until a fab file is wrong.
  - **`formats/kicadmod.nim`** reads a `.kicad_mod` file into a `Footprint` (`readFootprintFile`/`resolveFootprint`), Y-flipping and angle-negating at the boundary exactly as `kicad.readPcb` does, and registers itself as a `FootprintSource` on import — opt-in, the rule everywhere else here. `"Lib:Name"` resolves against a search path (`$VERAX_FOOTPRINT_PATH`, then `$KICAD10_FOOTPRINT_DIR`/`$KICAD9_FOOTPRINT_DIR`, then `/usr/share/kicad/footprints`) as `<dir>/Lib.pretty/Name.kicad_mod`.
  - **`assemble.nim`** builds a blank `Pcb` from a `Netlist`: standard layers top-to-bottom (`Pcb.layers` insertion order is stack order), a synthesized plain-FR4 stack-up, a rectangular outline with real `Edge.Cuts` geometry, and one placement per physical part in a deterministic grid (courtyard-extent spacing, sorted by designator so a re-run is byte-identical). **Every synthesized figure is an `Assumption`**, the `spice/models`/`tline.characterize` discipline for an invented input — nothing here reads a real stack-up, so a derived PDN or SI number resting on it should say so. **The hierarchy is not flattened**: `spice/flatten` could do this job (it imports nothing from `spice`), but its own doc comment says flattening is a *simulation-only* concession, and `pcb/` must not gain an edge to `spice` to borrow it regardless — so `assemble` walks the netlist itself, spelling a leaf inside instance `X1` as `hierName("X1", "U1")` = `"X1.U1"`, the same designator `spice/flatten` uses for a deck. `graph.bindComponent` gained an overload taking that path explicitly (`bindComponent(p, c, path)`), joining on the caller-computed hierarchical name rather than the flat designator, and `placementOf`'s existing `Placement.sections` fallback now also checks `p.component == c` so the reverse lookup works for a hierarchical part too. Resolution order for a part's footprint: its own `footprint` annotation, then (for a multi-channel package) `PackageDef.footprint`, then `footprint_unresolved` (`sevError`) — never silently skipped, since a placement with no land pattern is a board missing a part, not a smaller board. A footprint pad with no matching pin, or a pin with no matching pad, is `footprint_pad_unmatched` (`sevWarning`) — this is the check `docs/findings.md` (package pin count vs. footprint) was waiting on a board reader for. `writeBoard` is the one place in `pcb/` (besides `formats/kicad.nim` itself) that imports a format module directly rather than leaving that opt-in to the caller: there is exactly one writer, and `verify.nim`'s call site needs it to exist. This narrows, not breaks, "formats stay opt-in per import" — `import verax/pcb` still does not `export` `readPcb`/`writePcb`/`KicadDoc`, so that symbol surface is unchanged; only the compiled-in dependency graph is.
  - **`formats/kicad.nim`'s `writePcb` gained exactly one branch**, before its existing source check: a `Pcb` with `pcb.source == nil` and at least one layer renders through `formats/kicadgen.renderNewPcb` (which splices each placement's real `Footprint.source` — editing only `(at)`, `(layer)`, the `Reference` property and each pad's `(net)` — alongside a synthesized `(layers)`/`(setup (stackup))`/net table/`Edge.Cuts`/silkscreen-and-courtyard-graphics text) and is then **re-read through `readPcb`'s own mapping**, so the result is an ordinary read board (`mapped` populated, `attrs["kicad.node"]` set, `snapshotRev` stamped) and every subsequent edit takes the existing, tested regenerate/refuse path unchanged.
  - **`variant.nim` is data model and hooks only — no placer, no router, no selection policy.** `LayoutVariant` is keyed by `Netlist.name`, not by instance, matching how `verify.nim`/`schematic/render.keepFullSchematic` already spell a subcircuit's identity (a block instanced twice is drawn once) — a variant attaches to the *template*. The registry is the `PackageDef`/`PartPinmux` shape: pure data, no procs on a variant, no built-ins, duplicate `(subcircuit, name)` raises. "This instance uses variant X" is `attrs["layout.variant"]` on the instance `Component`, joining `netlist/layouthints.nim`'s `layout.*` family rather than living as a field here, since `pcb/` must not gain an edge *from* `netlist/` and the binding is authored on the netlist side long before any `Pcb` exists to hold it. `selectVariant` and `instantiateVariant` both **raise, naming what was asked for and what exists** — a stub returning the first fit, or one that copied geometry in blindly, would look like it worked while silently ignoring constraints or producing an unrouted-looking `Pcb` that is really just uncollision-checked copper, which is exactly the failure mode this codebase's named refusals exist to avoid.
- **Two traps that only showed up once real edits were tested against the live corpus, both now guarded in code and worth re-deriving if either guard is ever "simplified" away:** (1) `resolveInsertAnchor`'s "after the last existing sibling of the same head token" must skip a candidate already `markDeleted` — "rip up the last track on this net, add a new one" makes the last surviving `(segment)` in the file exactly the one a caller just removed, and anchoring an insertion there silently drops it (`sexp.markInserted` queued at a deleted node is never emitted — `markDeleted`'s own contract). Reproduced against `ecc83-pp.kicad_pcb` before the guard existed. (2) `doc.kids(root)` yields the `kicad_pcb` head token itself as `root`'s first child (same arena shape as every other list), so any anchor-resolution loop that does not skip non-list children will treat that atom's `classIndex("")` (unmatched, `high(int)`) as "later than everything" and anchor there.
- **Placement designator collisions are real, not hypothetical.** Real boards carry unannotated footprints with designator `""` or `REF**` (`microwave.kicad_pcb`'s first footprint is literally `(property "Reference" "POLY")` over a `REF**` value elsewhere in the corpus); `graph.addPlacement` raises on a duplicate key, so the reader synthesises a unique one (`REF**#1`, `REF**#2`, ...) and keeps the literal text in `attrs["kicad.reference"]`/`attrs["kicad.node.refText"]` — the latter is what a rename compares against at write time, since there is no `graph.renamePlacement` and a caller renames by setting `attrs["kicad.reference"]` directly (the same documented `touch`-yourself escape hatch every other direct-field-write bypass in `graph.nim` uses).
- **The KiCad >= `20251028` net-name-only format is not a hypothetical either.** `pic_programmer.kicad_pcb` (version `20260206`) has zero `(net N "name")` declarations; every reference is `(net "name")` by name alone. `KicadDoc.hasNetCodes` records whether the board declared codes *at all* (not merely whether `netByCode` is non-empty, which a numeric board using only net `0` would leave looking identical to a name-only one), and every write-side `(net ...)` formatter branches on it.

## `trace.nim`, `impedance.nim`, `tline.nim`: routing and closed-form transmission-line characterization

`trace.nim` stitches a net's copper into a routing tree; `impedance.nim` solves a stated cross-section in closed form; `tline.nim` joins the two into per-frequency Z0/loss, delay and an S-matrix. All three are read-only over a `Pcb` (never `graph.touch`) and none of them registers a contract quantity, attaches to `Design` or adds a device kind — that is the RF plan's follow-on, not this stage. Each module's own doc comment carries the load-bearing detail; this is the index of decisions, each naming the silent failure it prevents, the house standard `formats/kicad.nim`'s section above already sets.

- **`ckZone` is skipped, `ckFill` is not — the same rule `fem/extrude.extrudeCopper` already enforces, now enforced a second time from the routing side.** `graph.addZone` pushes one `ckZone` record per layer holding the *authored* pour outline onto `Pcb.netCopper`, so a naive walk of "every copper feature on this net" doubles the length of any net with a pour and, worse, treats the pre-clearance, pre-thermal-relief outline as if current actually returns through it. `extractRoutes` classifies `ckTrack`/`ckLand`/`ckViaPad`/`ckFill` and explicitly discards `ckZone` and `ckOther` in the same `case` statement that filters everything else, so this is not something a future refactor can accidentally widen back in without the compiler forcing a look at that line.
- **A via is a node, never a mid-edge event, and `RouteEdge.vias` is `0` by construction.** The only structural marker a layer change happened is a `Hole` tying two `Copper` rings together (`graph.attachPad`); a node carrying a `Hole` is excluded from the degree-2 collapse for exactly that reason. Collapsing through it would silently merge two physical layers — each with its own stack height, its own reference plane, its own `Z0` — into one `RouteSection` claiming a single width and a single layer. The alternative design (a `via` field on `RouteSection` marking a mid-run layer change) was rejected because it would let one section's `LineSpec` mean two different cross-sections depending on which half of it a caller read.
- **The degree-2 collapse is what makes the tree mirror branching, not merely "shorter."** A node with no pin, no via and no pour, touched by exactly two edges, is nothing but where KiCad happened to end one `ckTrack` object and start the next — necking under a pad, a manual "break track" edit, a re-route. Collapsing exactly those nodes and no others is why a driver feeding two receivers through a Y comes back as one shared trunk edge plus two branch edges rather than two independent point-to-point runs that happen to overlap, and why a plain point-to-point route — however many `ckTrack` fragments KiCad split it into — comes back as one `RouteEdge`.
- **The `Metres` question (`findings.md` §18, `rf_analysis_plan.md` Phase 5) is answered by *not* adding a type.** A computed length is a plain `float` in metres: `pcb/units.Nm` stays integer nanometres for the geometry it already serves (readers, containment tests, the spatial index), and `verax/units` stays electrical quantities (`Volts`/`Ohms`/…), which a board length is neither. `geometry.length`/`units.toMetres` return bare `float` rather than a fourth unit type, because a length here is used in ordinary arithmetic — summed across a chain, divided by a velocity for a delay, squared into an RLGC term — and a wrapper type would buy nothing further downstream already asks for while costing every consumer an unwrap. Settled here; do not reopen it without a concrete case a bare `float` actually gets wrong.
- **Empty `Zone.fills` refuses a reference-plane resolution rather than falling back to the authored outline — `reference_unfilled`, distinct from `route_no_reference`.** This is the same discipline `Zone.fills`' own doc comment states for `extrudeZones`: an unfilled board (or one read before a fill pass ran) has no real copper to test coverage against, and substituting `Zone.outline` would silently claim a return path with none of the real fill's clearances, thermal reliefs or priority-against-other-zones reshaping — the class of wrong answer that looks plausible rather than the class that gets noticed. The two refusals are named separately (`route_no_reference` for "no plane anywhere nearby at all", `reference_unfilled` for "the zones exist but nothing poured them yet") because they call for different next actions from whoever reads the report: state a plane, or run a fill pass.
- **Closed-form accuracy ceiling.** `impedance.nim`'s own doc comment states this once rather than at every formula: Hammerstad-Jensen and IPC-2141 are quasi-static closed forms validated over the geometry range each paper covered, not a field solve, and neither captures dispersion (`epsEff` is frequency-independent throughout). A number from here disagreeing with a fab's own field-solver report by a few percent is not a regression in either tool — this is the caveat `rf_analysis_plan.md` Phase 6 carries forward as the "same quantity names from four provenances" obligation: authored, closed-form, `mlin`, and eventually field-solved values must be nameable as the same quantity precisely because none of them is presented as more authoritative than its own method actually supports.
- **Roughness and conductor resistivity have no source in any board file this library reads.** `TlineSpec.roughness` defaults to `0` (smooth) and `TlineSpec.rho` to annealed copper at 20 degC (`1.72e-8` ohm-m); `tline.characterize` records both defaults as `Assumption`s, named to the edge they apply to, whenever a caller leaves them at the default — the same discipline every `spice/models` expander follows for an invented input. A loss figure computed at `roughness = 0` is a lower bound, not a measurement, and the report says so rather than presenting a smooth-copper number as if it were the real board's copper.
