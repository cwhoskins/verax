# `ibis` submodule

`src/nimcir/ibis/` reads a silicon vendor's IBIS (`.ibs`) file -- the Input/output Buffer Information Specification -- into a typed model of what a driver or receiver does at its pins: I/V curves, edge rates, die capacitance, package RLC, all as `typ/min/max` triplets. It depends on `nimcir/netlist` (to bind a model to a `Component`/`Pin`) and `nimcir/pcb` (to reach the board `Placement`); neither depends back. `src/nimcir/ibis.nim` is the hub over `types`, `parse`, `reader`, `attach` -- and unlike `nimcir/spice`, the *whole* submodule is in the hub, because there is no external tool to run.

**Scope: read the file, hand back the data.** This submodule owns *what the vendor says*. It does not simulate a buffer (an I/V table becoming a runnable device is `nimcir/spice/models`, keyed on `Component.kind`) and it does not judge a design against one (`nimcir/analysis`). The parser is real and covers the IBIS 3.2 core; everything past a parsed file is a skeleton.

- **`types.nim`** -- `IbisError` and the typed model (`IbisFile` / `IbisComponent` / `IbisModel` / `PinEntry` / `Triplet` / `IvTable` / `Waveform` / `RampSpec`). Two calls worth keeping:
  - **Every quantity is a bare `float` in SI base units, not a `nimcir/units` type.** IBIS states volts, ohms, farads, henries, amps and seconds through one `typ min max` grammar; a single generic `Triplet` cannot carry six quantity types, and a triplet type per quantity buys a transcriber nothing. `nimcir/spice/backend.SimVector` makes the same call. The rejected alternative -- distinct `VoltsTriplet`/`OhmsTriplet`/... -- is recorded so it is not "fixed" later.
  - **`Triplet` records presence per corner.** A `min` of `0.0` and a `min` that was `NA` are different claims about a part, and `NA` appears anywhere a number may. `get` **raises `IbisError` on an absent corner** rather than returning `0.0`, mirroring `SimResult.[]` raising instead of letting a `FieldDefect` escape. `has` is the non-raising check.
  - `IbisModel.raw` / `IbisComponent.raw` keep the whole block as lexed, so a subparameter this version does not model is still reachable.
  - Deliberately not modelled: `[External Model]` / `[External Circuit]` (SPICE/VHDL-AMS/Verilog-AMS references), `[Node Declarations]`, algorithmic AMS, and the IBIS 5+ EBD/ICM board-description families. Each such keyword still survives in `IbisFile.sections`.

- **`parse.nim`** -- the lexer, kept separate from `reader` so an unmodelled keyword round-trips. `splitSections` returns a tree of `IbisSection`; `canonicalKeyword`, `parseIbisNumber`, `parseTriplet`, `isNA` are the shared primitives. What the grammar forces, each because getting it wrong is silent:
  - **The comment character defaults to `|` but `[Comment Char]` redefines it**, effective from that line on. A hard-coded `|` mis-parses a file that redefines it and then uses `|` as data. Parsed from the raw keyword line, *before* comment-stripping, so `[Comment Char] |_char` (redefining to the current char) still works.
  - **Keywords are case-insensitive and space/underscore-equivalent** -- `[GND Clamp]` == `[GND_Clamp]`. Hence `canonicalKeyword` (lowercase; every run of spaces/underscores to one `_`).
  - **A keyword's `[` is in column 1**; a `[` elsewhere is data.
  - **`[End]` ends the file** -- text after it is ignored, not an error.
  - **`parseIbisNumber` is shaped like `netlist/formats/spice.parseSpiceMagnitude`**: a `bool` + `var` out-param that refuses rather than guesses. `M` is mega, `m` is milli (case is load-bearing); `meg` is not IBIS; a digit after the prefix (`2k2`) is rejected -- IBIS has no RKM notation.
  - Deliberately not enforced: the spec's 120-character line limit. Real vendor files exceed it.

- **`reader.nim`** -- builds the typed `IbisFile` over `splitSections`. Implements the format contract's spelling (`readIbis` / `readIbisFile`, names that do not stutter the format, as in `netlist/formats/common`). **No writer** -- emitting IBIS is not a stated need and a half-writer is worse than none. Two behaviours carried from `formats/spice.nim`: every failure is an `IbisError` **with line context** where the lexer can supply it, and **an unrecognised keyword degrades, it does not error** -- it stays in `IbisFile.sections` and nowhere else, which is exactly why a 3.2-shaped reader still opens a 7.x file. Deliberately not parsed into the typed layer: `[Rising Waveform]`/`[Falling Waveform]` fixtures beyond their lumped R/L/C, `[Add Submodel]`, `[Driver Schedule]`, `[Model Selector]` beyond its choice list.

- **`attach.nim`** -- the one module importing both `nimcir/netlist` and `nimcir/pcb`, and the reason the submodule sits above both. `bindIbis(nl, designator, file)` ties one `[Component]` to a reference designator and **verifies every `[Pin]` name maps onto a real `Pin`**, raising `IbisError` naming the first mismatch -- that check is the whole value of the binding and it is cheap. `modelFor` and `placementOf` are thin lookups off a binding. Deliberately not here: turning an I/V table into a `spice/models` behavioural model, and turning an edge rate into an `analysis` timing budget -- both named in `docs/architecture.md`'s ownership table as other submodules' work.
