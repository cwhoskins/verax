# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- Run all tests: `nimble test` (compiles and runs every `tests/t*.nim` file via `tests/config.nims`, which adds `src` to the path). The `nimcir/spice/ngspice` backend tests in `tests/test_spice_ngspice.nim` are skipped automatically (not failed) when `ngspice` isn't found on `PATH`.
- Run a single test file: `nim c -r --path:./src tests/test_netlist_core.nim` (or `tests/test_netlist_spice.nim`, `tests/test_netlist_dsl.nim`, `tests/test_spice_probes.nim`, `tests/test_spice_transform.nim`, `tests/test_spice_extract.nim`, `tests/test_spice_ngspice.nim`, `tests/test1.nim`)
- Type-check a module without running anything: `nim check --path:./src src/nimcir/netlist.nim`
- Package metadata (version, license, dependencies) lives in `nimcir.nimble`; the library has no dependencies beyond the Nim standard library (`requires "nim >= 2.2.10"`)
- Run the DSL example script: `nim c -r --path:./src examples/divider.nim` (builds a netlist with `nimcir/netlist/dsl` and prints it as SPICE; not part of `nimble test`)

## Architecture

`nimcir` is a proprietary-licensed Nim library. `src/nimcir.nim` is the top-level package module; it is intentionally *not* a re-export hub — submodules (`submodule.nim`, `netlist.nim`, `spice.nim`) are imported directly by their own path (e.g. `import nimcir/netlist`), not through `nimcir.nim`.

### `netlist` submodule

`src/nimcir/netlist/` models an electronic circuit netlist in memory and reads/writes it to netlist file formats.

- **`types.nim`** — the core, format-agnostic data model: `Netlist`, `Net`, `Component`, `Pin`, all `ref object`s. The graph is deliberately built with *direct object references* in both directions (`Pin.component`/`Pin.net`, `Net.pins`, `Component.pins`, `Netlist.parent`/`Netlist.children`) so it is fully walkable from any starting point — not just reachable through the name-keyed `OrderedTable` dictionaries (`Netlist.nets` by net name, `Netlist.components` by reference designator). Nim 2.x's default ORC GC collects the resulting reference cycles automatically. Every entity has an open-ended `attrs: OrderedTable[string, string]` bag for format-specific extras, keeping the core schema format-agnostic.
- **`graph.nim`** — the only place allowed to mutate the graph's back-references (`addComponent`, `addNet`, `addPin`, `connect`/`disconnect`, `removeComponent`, `addChild`, `addPort`, `clone`, `instantiate`). Code elsewhere must go through these procs rather than hand-setting `.net`/`.pins`/`.component`/`.parent` directly, or the bidirectional links will get out of sync.
- **Hierarchy model**: a "sub-netlist" is a child `Netlist` hung off a `Component` whose `subNetlist` field points at it (e.g. a SPICE `X`/subcircuit instance). `instantiate()` deep-clones a template `Netlist` per instance via `clone()`, so each instantiation gets independent `Net`/`Component`/`Pin` objects rather than sharing one template — except nets registered in the `globalNets` table passed to `clone`/`instantiate` (e.g. SPICE node `"0"`), which are reused as the *same* object across every hierarchy level to match real ground/global-net semantics. A hierarchical instance's pins connect normally to nets in the *parent* scope; each such pin's `hierNet` additionally points straight at the matching port `Net` inside `component.subNetlist`, so hierarchy boundaries can be walked in either direction without name lookups.
- **`formats/`** — pluggable file-format readers/writers. Every format module implements the same contract: `readNetlist(s: Stream, name = ""): Netlist`, `writeNetlist(nl: Netlist, s: Stream)`, plus `readNetlistFile`/`writeNetlistFile` path wrappers. Format modules only depend on the core types/graph API — the core never depends on a format. `formats/spice.nim` is the only format implemented so far (SPICE `.cir`/`.net` decks); a `formats/kicad.nim` can be added later using the same contract. `formats/common.nim` holds the shared `NetlistFormatError`.
- **SPICE specifics** (`formats/spice.nim`): parses positionally per SPICE's reference-designator-prefix convention (R/C/L/D/Q/M/V/I map to fixed pin-name templates via `deviceKindByPrefix`/`pinTemplates`, and the inverse `designatorPrefix(kind): char` derives the letter back from a `kind` string; `X`/`U` resolve against `.SUBCKT`/`.ENDS` blocks, supporting forward references and nested subcircuit-instantiates-subcircuit). `.MODEL` cards are stored verbatim in `Netlist.models` (passthrough, not structurally parsed); other simulation-control directives (`.OPTIONS`, `.TRAN`, `.PARAM`, ...) are topology-irrelevant and are skipped on read. Unrecognized device-designator prefixes fall back to generic `pin1..pinN` pins rather than erroring. Because raw SPICE has no native concept of pin *type* (power/ground/input/output), `Pin.kind` fidelity through a SPICE round-trip is best-effort only — this is an inherent format limitation, not a bug. `writeNetlist`/`writeNetlistFile` take an optional `cards: seq[string]` (raw control/analysis lines, e.g. `@[".op"]`) written just before `.END`; empty by default, so plain topology output is unaffected. This is what `nimcir/spice/ngspice` uses to attach an analysis card without duplicating device-line formatting.
- **`dsl.nim`** — an opt-in Nim-macro DSL (`import nimcir/netlist/dsl`) for authoring a `Netlist` directly in `.nim` source instead of hand-calling `graph.nim` or parsing a file format. `netlist("name"): ...` builds a flat netlist from `net`/`component` (with nested `pin`) statements; `subckt("name", [ports]): ...` builds a free-standing template `Netlist` (never registered into any parent), instantiated later via `instance designator, templateIdent, [portNets]`, which expands straight to `graph.instantiate`. Net/component names given as bare identifiers are bound as real Nim `let`s so later statements can reference them (a typo is a compile error); `kind`/`name`/`partNumber` are the only typed "known fields" and get direct field assignment, while any other `key = value` pair lands in that entity's `attrs` bag. The DSL only ever expands into calls on the `graph.nim` API — like everywhere else in this submodule, back-references are never hand-set outside `graph.nim` itself. A `component` block may additionally contain one `simReplace kind = "...": pin ..., ...` statement (see the `spice` submodule below) — that statement only ever assigns `Component.simReplace`, so it never mutates the component it's attached to.

### `spice` submodule

`src/nimcir/spice/` runs simulations against a `Netlist` through an external SPICE backend (currently `ngspice` only) and provides simulation-only netlist transforms. It depends on `nimcir/netlist` (core types/graph, and `formats/spice` for deck serialization); the core never depends back on it. `src/nimcir/spice.nim` is the hub, exporting the backend-agnostic pieces (`backend`, `probes`, `transform`, `extract`) — a concrete backend like `ngspice` is opt-in per-import, same as file formats under `netlist/formats/`.

- **Simulation-only component replacement** (`Component.simReplace: SimReplacement`, defined in `netlist/types.nim` alongside `Netlist.models` as a pragmatic simulation-aware field on an otherwise format-agnostic core type): records "for simulation purposes, replace this component with a device of `kind`, wired as `pinNets` (pin name -> net *name*) describes", set via the DSL's `simReplace` statement co-located inside a `component` block. It never mutates the component itself — it's inert data until `spice/transform.materializeSimNetlist(nl, globalNets)` clones `nl` and applies every stored `simReplace` (recursing into `nl.children`) via `spice/transform.replaceComponent`. The real design netlist passed in is never mutated. `graph.nim`'s `clone()` copies `.simReplace` by reference (treated as immutable once built).
- **`transform.nim`** — `replaceComponent(nl, oldDesignator, kind, pinNets, ...)` removes the old component (`graph.removeComponent`) and adds a new one of `kind`, auto-deriving a SPICE-correct designator (via `formats/spice.designatorPrefix`) rather than reusing the old designator's letter, since SPICE infers device type from that letter, not any `kind` field.
- **`probes.nim`** — `addVoltageProbe(net)` is a pure label helper (no graph mutation: ngspice's default `.control`/`write` already dumps every node voltage). `addCurrentProbe(nl, pin)` *does* mutate: it splits the pin onto a fresh net and inserts a 0V voltage source in series, because ngspice only exposes branch current for voltage sources/inductors. Both probe/replacement mutators are meant to run on a clone or a `materializeSimNetlist` result, never the real design netlist.
- **`extract.nim`** — `extractInstance(comp, globalNets)` pulls a hierarchical component's `subNetlist` out standalone (thin wrapper over `clone()`). `extractSubcircuit(nl, name, designators, globalNets)` extracts an arbitrary *flat* selection of `nl.components`: clones the whole netlist, computes boundary nets from the *original* graph (any net touching both a selected and a non-selected component) and promotes them to ports, then removes everything not selected.
- **`ngspice.nim`** — `writeDeck`/`writeDeckFile` are thin wrappers over `formats/spice.writeNetlist`'s `cards` param. `run(nl, cards)` supports at most one analysis card per call (ngspice's default `write` only keeps the last analysis's plot if more than one is given — confirmed empirically, not assumed) and treats "a parseable raw output file exists" as the success signal rather than the process exit code, which was found to be unreliable (a clean run with only benign warnings can still exit non-zero; a malformed deck can SIGABRT). Output is parsed from ngspice's ASCII rawfile format (`set filetype=ascii` + `write <path>` inside `.control`); `.ac`'s `Flags: complex` layout is unimplemented and raises `SpiceSimError` rather than being silently misread. Probing an internal node of a *nested* subckt instance via ngspice's hierarchical node-path syntax is unsupported — use `extract.nim` to pull the region of interest to the top level first instead.
