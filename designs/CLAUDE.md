# Designs and templates

A design is an ordinary `.nim` file using `verax/contract/dsl` that ends with `quit(verifyMain(d))`, so `nim c -r --path:./src designs/foo.nim` is the same check `./bin/verax check designs/foo.nim` runs, without the wrapper (~1.1 s cold, ~0.7 s warm). This is the primary loop. `nimble verify` checks every design here and every file under `templates/`.

Exit codes are graded: `0` clean, `1` a claim failed, `2` structural problem, `3` a claim nothing could check, `4` a requested capability is unavailable here, `5` the design did not compile (only `verax check` produces `5`, and it is separate on purpose — told only "it failed", a reader edits the circuit to fix a syntax error). Flags, forwarded to the design binary: `--offline`, `--caps=op,dc,ac,tran`, `--verbose`, `--strict`.

## The designs

`ts808_drive` (single-supply overdrive), `sensor_node` (LDO + I2C), `aa_filter` (4th-order Sallen-Key), `charge_pump` (Dickson doubler, whose `settled_rail` claim found a 403 mV edge spike across COUT's ESR and ESL where a hand-run with ideal capacitors reported 5.1 mV of droop), `wien_osc` (oscillator -- kicked into life with an `.ic`, then measured for rate, swing and distortion by the `oscillator` role), `riaa_preamp` (stereo, instancing `lib/riaa.nim` twice, and the first design to claim a **two-subject** quantity: a `channel_match` role binds the two `gain_stage` instances with `roleRef` and claims `gain_delta_max_db <= 0.5 dB` across the audio band — two copies of one `subckt` measure exactly 0 dB apart, and a 1% feedback-resistor error on one channel moves it to 67 mdB; it is also the worked example of **multi-channel packaging** — `lib/riaa.nim`'s amplifier moved from `NE5534` (single) to `NE5532` (a genuine dual, deck-identical since `idealOpAmp` never touched the rails), and `with = u10.section("A"|"B", "U1")` tags the two `XL.U1`/`XR.U1` instances as the two halves of one physical `U10`, so `validatePackages` checks both sections' `V+`/`V-` land on one rail; `aa_filter` does the same for `U1A`/`U1B` via the flat `u1.assign(d.netlist, ...)` path) and `lt8640a_buck` (the datasheet reference design, simulated through **two** Nim-authored XSPICE code models -- `lib/lt8640a_avg.nim` for the rail voltage and `lib/lt8640a_sw.nim`, peak current mode at fifty timepoints a cycle, for the ripple -- with `spice/transform.selectSimModel` picking by what is being asked, and the first design to claim a **current**: `current_path` reads L1's 905 mA triangle against the 879 mA the design equations fix, and its 49% of the part's own stated saturation current -- now stated as one `switching_regulator` instance covering the way up, the settled ripple, the inductor current, a 1 A **load step** measuring 21.3 mV of droop and 27 us of recovery, and 70.1 dB of **ripple rejection** at 100 kHz by the tone method, which is the only method that reaches it: an `.ac` sweep through an XSPICE code model returns exactly zero output, because a code model contributes to the AC matrix only if it sets `AC_GAIN`) and `carrier` and `sensor_head` (each a **module when imported and a program when checked**, split by `when isMainModule`: a board states what is plugged into it for the bench, and `asSubcircuit` drops the connectors so those assumptions cannot leak into a system) and `system_sensor_rig` (both boards wired through an explicit cable — the design that found an 8.71 ohm anti-resonance neither board has on its own, on a sensor head that passed its own check by 30x) and `param_filter` (two Sallen-Key sections a decade apart, both built by `lib/filters.sallenKeyLP(fc, r, q)` — no component value appears in the design file, so the claims check the design equations rather than checking that somebody did the arithmetic twice), `divider_net` (a voltage divider and a current divider both stated as a **total impedance and a ratio**, and the three-resistor network that replaces the voltage divider's bottom leg with the current divider -- both taps must read the same 2.5 V, which is the substitutability property measured rather than asserted, and the split itself is read at a sense node two levels down inside the instance because both legs return to the same ground and nothing in the parent netlist witnesses it; the two taps are additionally **swept** rather than sampled -- `source_sweep` measures the ratio as a slope over the whole input range, which a wrong network with a compensating error would still pass at one bias, and `load_sweep` measures 18.75 kohm of output resistance at both taps, which is the half of substitutability no node voltage witnesses) and `i2c_eeprom` (a dummy MCU and an M24C64-U EEPROM holding an actual **conversation** -- two Nim-authored event-driven code models on a shared open-drain bus, reading the 128-bit unique ID out of the identification page, writing to the memory array, acknowledge-polling through the part's real 5 ms write cycle and reading back, with the controller's verdict pin carried out through a `dac_bridge` so the outcome is a `settled_v` claim like any other; SDA and SCL are **real analog nets** with pull-ups, bus capacitance and a `bidi_bridge` at each line, so the `i2c` role's claims have resistors to find) and `adj_regulator` (two LM317 rails sized from the datasheet equations in `lib/adjreg.nim` -- the part is a *value* carrying its reference, ADJ current, range, dropout, minimum load and thermal resistance, and for simulation a `SimReplacement.build` swaps it for the **loop** it closes, an error amplifier holding the reference between OUT and ADJ plus a current source for the ADJ pin, so ngspice solves the divider in the netlist and nothing in the design file is compared against itself: drop the `iAdj*rAdj` term and the 5 V rail measures 5.036 V and misses its 0.5% band; the loop now closes through a **floating series pass element** fed from the IN net, so both the input current and the ripple rejection fall out of it rather than being declared, and two `linear_regulator` roles claim a load step, line regulation of 0.0107 %/V against the datasheet's 0.01 %/V typical, and 62.9 dB of rejection at 120 Hz **by both methods at once** -- a `.tran` tone and an `.ac` sweep, two solvers agreeing to 0.002 dB). The **`xbar_*` family** is the first *product* here rather than a circuit demonstrating one feature: an Ethernet-controlled 4x4 50-ohm RF crossbar powered from PoE or USB-C, split into five chunk designs (`xbar_poe`, `xbar_usbc`, `xbar_power`, `xbar_rf`, `xbar_control`) each a module-and-program like `carrier`, and one system (`xbar_switch`) that instances all five through `asSubcircuit` and drives both inlets at once. What it demonstrates: (1) the **`safe_default` role** (`lib/xbar_parts.nim`, the second role written outside the library after `i2c_transaction`) -- one `dc_voltage <= fraction*rail` claim per line, checking that the ADG904 enables sit low at power-up held by `controlPulldowns`; a *reversed* OR mux is caught the other way, collapsing `vsys`/`v3v3` so the `power_rail` claims fail. With the ADG904 now a real absorptive `rf_switch` model (`lib/adg904.nim`), the claim finally *means* what it says -- enable low ⇒ every RF port sitting in its internal 50 ohm -- rather than passing because `expandPinModels` grounds an unmodelled pin. `xbar_rf.nim`'s bench also routes RIN1 → m1 → ROUT1 (EN1/EN5 driven) and checks the routed path carries a tone while the unselected midplane rails stay at ground; it is also the worked example of the **component-array collapse** (`schematic/arrays.nim`'s `buildComponentArrays`) -- its eight SMA connectors and eight ADG904 switches each collapse to badged boxes/symbols (the ADG904's absorptive internal termination replaced the board's own `RT_*` resistors), taking the sheet from ~27 drawn parts to a dozen or so, while the eight `CBY*` decoupling caps on one rail pair stay a visible `parallelStackKind` stack of eight -- the all-common decline this feature needs to not steal a bank. Each of those two groups in fact splits **two ways** -- input-side vs. output-side (`connector x4` + `connector x4`, `rf_switch x4` + `rf_switch x4`) -- because `RFC`/`RF` bind to `bus rin` on one half and `bus rout` on the other: eight *distinct* nets sharing no value at all, so the split is visible only through declared bus membership (`arrays.nim`'s `splitKeyOf`), never through a repeated net. The same mechanism also splits the board's 24 enable/address pulldowns into an `en` `x8` and an `a` `x16`. A bundle no longer caps collapse at two endpoint entities -- uniformity is the whole test (`bundles.collapsible`) -- so the `m` midplane bus, wired identically across all eight switches, now draws as one real bus tree between the two `rf_switch x4` boxes instead of degrading past three entities; `rin`/`rout` similarly collapse from bare per-carrier net-label tags into one real bus wire each, spanning the two arrays either bus is distributed across (a `brCollapsed` bundle now declines an array candidate only when hiding its own members would leave that bundle with fewer than two *placeable* entities, not on the old "any member touches some collapsed bundle" rule, and a `bundled`-but-never-merged distributed port -- one member per carrier throughout -- is drawn and routed by the array itself, reusing the bundle's own tag, rather than deferring to it). `a` keeps its bundle-drawn merged tags (`"a(0, 1)"`, `ArrayPort.bundleFamily`) since every switch there genuinely merges `A0`+`A1` into one pin; `en` reaches the same array-owned code path as `rin`/`rout` but its own placement happens not to route as a tree, so it falls back to net-label tags exactly as an unroutable bundle always has. (2) The **cannot-check list is a deliverable**: `xbar_switch.nim`'s header carries it. Two entries closed while this family was live -- coupled inductors (§26, `spice/models/magnetics` + a `dc_path_exists` barrier claim on the flyback `T1` and the PoE common-mode choke) and the switch device model (§26, `spice/models/switch`) -- and what is left is stated precisely: transmission lines / S-parameters, rail sequencing, a logic-state quantity, `esd_clamp`, and a two-port AC transfer for the choke's rejection. (3) A whole-system `.op` carrying **both** the LT8640A switching code model and the 48 V PoE rectifier bridge does not converge, so `equipXbarPower(d, prefix, withBuckModel = false)` swaps in `buildIdealBuck` (an ideal source on SW) for the system while the chunk bench keeps the real model; and the switcher's steady-state claims (ripple, PSRR, load step) are declined even in the chunk bench because its input, fed through the OR diodes rather than a stiff source, collapses the switching model's timestep -- `lt8640a_buck` exercises those against a stiff 12 V input instead. `spi_memories` (three SPI controllers, each sharing one bus between three 1-Mbit serial SRAMs) is a structural worked design: it exercises the interface array (`iface spi, spiInterface(3), count = 3`), chip-select-by-`narrow`, a 9-bit write-protect bus threaded from the MCU into each `lib/spi_memory.nim` sheet, loop instantiation of the nine memories, and — the reason `lib/stm32h563.nim` exists — **pin capabilities**: each controller `port` names its peripheral (`peripheral = "SPI1"`) and the real STM32H563 pins it lands on, so `validatePinmux` rejects a clock routed to a pin that cannot mux it, and the second and third chip selects of each triple are declared software GPIOs (`functions = {"cs_1": "GPIO", "cs_2": "GPIO"}`) rather than a hardware NSS. It is also the worked example of the **subsheet-array collapse** (`schematic/arrays.nim`): the three memories on one controller share that controller's SCLK/MOSI/MISO, so `arrayPlan` sub-groups the nine `SPI_MEMORY` instances by SPI bus and the archive schematic draws **three `SPI_MEMORY x3` boxes**, one per controller, rather than nine separate ones — the readiness report is unchanged because the checks read the netlist, not the picture. `rf_frontend` is the smaller structural sibling and the first design whose interface is **defined in the design file itself** rather than pulled from `verax/netlist/interfaces/std`: `interfaceDef("rf_ctrl")` bundles a radio front-end's control lines (`rf_en`, the transmit/receive select `trx`, and a 4-bit `gain` word for the receive VGA), gives it `controller`/`frontend` modports, and — the point of it — carries `implies "rf_keydown"`, a role also defined in the file (two `dc_voltage` claims that the enable and T/R select power up low, held by board pull-downs), so instantiating the interface is what attaches the power-up-safety check, exactly as `i2cInterface()` implies `"i2c"`. The module sheet takes its own `rf_ctrl_sheet` def with only the `frontend` modport — the `spi_memory_link` vs `spiInterface` split — so a sheet that never drives the bus is not flagged for having no controller. `usb_hs_link` is the differential-pair worked example: a USB-C receptacle through a common-mode choke, 22R series termination and an ESD clamp into a transceiver, plus a second, unrelated pair of links declared with `iface aux, diffPairInterface(), count = 2` — the interface-array mechanism `spi_memories` already uses, here producing two independent `diff_pair` role instances from one statement. `diffPairInterface()` is a two-signal `InterfaceDef` (`p`/`n`) that `implies "diff_pair"`, exactly the `i2cInterface()`/`"i2c"` shape, so a differential pair needed no new declaration mechanism at all. `diff_pair_symmetry` (`contract/evaluators/diff.nim`) walks both legs' series parts hop for hop and is the one claim this design makes — mismatching R1/R2's value (a 0R stand-in for a wrong-value termination resistor) fails the claim by name and reverting it passes again; `z_diff`/`intra_pair_skew` are registered quantities (`usb2Interface()`, used in `templates/diff_pair.nim` and in tests, states USB 2.0's real 90 ohm target) but always come back NOT CHECKED, since nothing in `pcb/` yet accumulates trace length or solves a stackup for them — which is why this design, meant to check clean, claims only symmetry. It is also the worked example of the **declared-pair floor** on the component-array collapse (`schematic/arrays.nim`): `R1`/`R2` (the 22R termination), `D1`/`D2` (the ESD clamps) and each `count = 2` `aux` lane's own `R3`/`R4`/`R5`/`R6` each draw as one `x2` box, since one pin of each pair is bound to the same `diff_pair` interface instance — the same "unambiguously one thing, not a coincidence" evidence the bypass-bank floor reads off ground/rail identity, carried here by the declared interface instead. `R1`/`R2`'s *other* pin sits on `dp_choke`/`dn_choke`, real nodes distinct from `hs_p`/`hs_n` (L1 and the resistors themselves sit between them, so they cannot be the same interface net without shorting out the parts that make them a pair) — tagged with the schematic-only `bus hs_choke, nets = [dp_choke, dn_choke]` (and `bus hs_ext`, `bus aux0_ext`, `bus aux1_ext` further upstream) rather than another `iface`: same `bus.name` net attr `bundles.nim` groups on, none of `iface`'s role/assertion side effects. That merges every part along both differential paths — `J1`, `L1`, `R1`..`R6`, `J2` included — to one interface-style pin per side, the way `U1`'s already did, with no new claims and the design still checking clean. Shared parts and subcircuits live in `designs/lib/`, which `nimble verify` does **not** pick up because `listFiles` is not recursive — they are compiled as dependencies of the designs that import them. A file that imports an XSPICE code model for its `ModelSpec` needs `-d:xspiceSpecOnly`, which `verax check` passes for a design and which `tests/test_xspice_i2c_eeprom.nim.cfg` -- a per-file Nim config, and the reason `.gitignore` re-includes `/tests/*.nim.cfg` -- passes for the one test that does; without it the compiler tries to build the model's FFI against ngspice headers it has no reason to need. `lib/lt8640a.buckSheet` (used by `designs/datalogger`, not yet catalogued here) now sizes its input and output bulk capacitance as real banks rather than one oversized part -- `lib/capbank.capBank` splits a ripple-sized total into `spec.series`-valued parts no larger than a stated case, with `dielectric`/`voltage_rating` stated on every part so `spice/models/derating` corrects against a stated fact instead of an assumed X7R at an assumed 2x rating, which is what a bank not stating either used to get.

## Seeing what was actually simulated

`VERAX_KEEP_DECKS=<dir> ./bin/verax check <design>` copies every deck handed to ngspice into `<dir>`. The fragments are derived, not authored, so this is the only way to check a surprising number against the circuit that produced it. **`--keep-runs=<dir>` (or `$VERAX_KEEP_RUNS`) keeps the *results* too** -- per simulation, `run000.cir`, `run000.raw` and `run000.log`, plus `run000.svg` and its `run000.json` scene of the derived fragment, plus an `index.txt` naming each run's analysis, netlist, plot and point count, so `run001` can be identified as the PDN sweep of `vdd` without opening it. The deck is not copied there but *written* there, so it is the one that ran and re-running it in place reproduces its rawfile; the rawfile is ngspice's own ASCII format, so `load run001.raw` in ngspice brings the whole curve back. `--save-currents` adds device terminal currents (`@r1[i]`) to what is saved, which is the one category ngspice does not save by default -- `.op`/`.tran`/`.dc` only, see `src/verax/spice/CLAUDE.md`. Neither flag can move a measured number, which `tests/test_spice_keep.nim` pins.
